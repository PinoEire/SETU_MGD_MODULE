# Lifecycle sample

Makes a game survive Home, app switching, incoming calls, screen off, the notification shade and the Android back gesture. The two scripts live in `Scripts/Shared/` because every scene in this app uses them (the scene builders attach them through `AddPauseMenu`); this folder keeps the demo and the explanation. `LifecycleGuard.cs` goes in every scene that can pause: it saves and pauses on `OnApplicationPause(true)` (the last reliable moment before Android may kill the process), pauses without saving on `OnApplicationFocus(false)` (the shade, a dialog, the keyboard: the process is not at risk), sets `Time.timeScale` and `AudioListener.pause`, and raises `PausedChanged`. The pause state is static, so nothing needs a reference to the guard. Resuming is only ever the player's choice. `PauseMenu.cs` goes on the Canvas: it shows the pause panel from that event, handles the Resume button, and toggles pause on Android back (which the Input System delivers as Escape) when `backTogglesPause` is on; turn it off in a scene where back already leaves the scene. There is no Quit button. Android sends no focus callback for system UI that does not take focus (the status bar peek of a full-screen game, a heads-up notification, the volume popup), so those do not pause; the open shade, quick settings, recents, the assistant and dialogs do.

Copy those two scripts and gate your own gameplay with `if (LifecycleGuard.IsPaused) return;` at the top of `Update`, because `timeScale = 0` does not stop `Update`. `LifecycleDemoHud.cs` is demo scaffolding only: a spinner, two clocks, a tone, a saved tap counter and an on-screen callback log so the five-row lifecycle matrix from Week 2 Lab B can be ticked on the phone without Logcat. The guard's pause logic is tested in `Assets/_Game/Editor/Tests/LifecycleGuardTests.cs`. Design notes are in the `MGD_MODULE_GDD` vault, note `Samples/Lifecycle`.
