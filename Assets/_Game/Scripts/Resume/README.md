# Resume sample

Timed Awaitables that survive pause and resume (Week 11 Lab A, Part C). `ResumeGuard.cs` is the pattern to copy: every timed await takes its token from one `CancellationTokenSource`, linked to `destroyCancellationToken` and `Application.exitCancellationToken`. Pausing cancels the source, so every await stops and throws `OperationCanceledException`, which is caught as the expected path; resuming makes a new source and starts the loops again, and because the old one is always cancelled first, no loop can run twice. The one-shot boss timer keeps its remaining time across a pause and never restarts once it has fired (`PausableCountdown.cs` holds that bookkeeping); the repeating wave loop starts a fresh interval. `ResumeGuard` needs `LifecycleGuard` from `Scripts/Shared/`, because this game resumes when the player taps Resume. Without it, call the stop and start from your own pause and resume, and keep the lab sheet's guard against the `OnApplicationPause(false)` Android sends at launch. `OfflineProgress.cs` is the idle-game half: it saves `DateTime.UtcNow` on `OnApplicationPause(true)` and compares it on return, clamped to 0 and a maximum (8 hours by default), which survives the process being killed where `Time.time` cannot.

`ResumeDemoHud.cs` is demo scaffolding only: the boss countdown, the wave count, the last offline reward and an on-screen log, so the six-case resume matrix can be checked on the phone without Logcat. The countdown and the offline clock are tested in `Assets/_Game/Editor/Tests/ResumeTests.cs`; the worked matrix is `docs/qa/resume-tests.md`. Design notes are in the `MGD_MODULE_GDD` vault, note `Samples/Resume`.
