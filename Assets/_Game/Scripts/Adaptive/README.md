# Adaptive sample

The Week 7 patterns. `PerformanceMode.cs` in `Scripts/Shared/` is the Balanced / High FPS setting: Balanced asks for 60 fps at render scale 1.0, High FPS for 120 at 0.8, the choice is saved as `perf_mode` in PlayerPrefs and applied before the first scene loads, and every apply logs `perf_mode=<mode> high=<bool> target=<fps> scale=<scale>`. It is static because everything it changes is global. The High FPS toggle is on the pause card of every scene. A static method cannot be picked in a UnityEvent, so the toggle calls `PauseMenu.OnHighFpsChanged`, which forwards to `PerformanceMode.SetHighFps`; the menu sets the toggle from the current mode with `SetIsOnWithoutNotify` each time the panel opens. `AdaptiveBootstrap.cs`, also in `Scripts/Shared/`, is created once by the Launcher and kept across loads: it subscribes to `ThermalEvent` and `PerformanceBottleneckChangeEvent` and logs `[AP]` lines for logcat. Copy those two, and `ThermalOverlay.cs` from this folder: frame time plus the thermal metrics on screen, with no allocation in the steady state. It has two labels where the deck has one: the numbers go through allocation-free `SetText`, and the warning, bottleneck and mode names go in a string rebuilt only when one of them changes. The tests are `PerformanceModeTests`, `ThermalOverlayTests` and `SoakTimerTests` in `Assets/_Game/Editor/Tests/`.

`SoakTimer.cs` and `HeatLoad.cs` are demo scaffolding for the Lab B thermal soak. The timer shows the time since the soak started and when the warning level first left `NoWarning`, and logs a `[Soak]` line every minute; the load stacks faint (5% alpha) full-screen layers so the GPU works hard enough to warm the phone, and Off, Warm and Hot cycle from a button. Adaptive Performance needs its Android provider ticked (Project Settings > Adaptive Performance, Android tab) and *Initialize on Startup* on; its settings live in `Assets/Adaptive Performance/`, where Unity creates them. Design notes are in the `MGD_MODULE_GDD` vault, note `Samples/Adaptive`.
