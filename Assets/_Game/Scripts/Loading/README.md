# Loading sample

The Week 5 Lab B pattern, used by every scene change in this app. `SceneLoader.cs` in `Scripts/Shared/` is the one loader: the Launcher creates it once on a `DontDestroyOnLoad` object (a later copy destroys itself), and everything loads through `SceneLoader.Instance.Load(...)`. It shows the loading screen, loads with `allowSceneActivation = false`, steps frames while `progress < 0.9f` with the bar at `progress / 0.9`, then allows activation and awaits the operation; while it runs, back and a second load do nothing, and it logs `[perf] scene <name> loaded in N ms`. `MenuReady.cs`, also in `Scripts/Shared/`, logs `[perf] interactive X.XXs` on the menu's first frame. Copy those two. The tests are in `Assets/_Game/Editor/Tests/SceneLoaderTests.cs`.

`LoadingDemoHud.cs` is demo scaffolding with one deliberate bug: *Load with the bug* runs the classic `while (!op.isDone)` loop, which never ends while activation is not allowed, so you can see what an infinite loading screen looks like (the bar is full, progress sits at 0.90 and frames keep ticking, but the scene never appears). A watchdog explains after 3 s and then lets the load finish; never copy that loop. *Load heavy scene* loads `LoadingHeavy` through the real loader. Design notes are in the `MGD_MODULE_GDD` vault, note `Samples/Loading`.
