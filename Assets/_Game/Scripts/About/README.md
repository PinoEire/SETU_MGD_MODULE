# About sample

The Week 8 Lab A build stamp. `BuildStamp.cs` in `Scripts/Shared/` writes the About screen's four lines once in `Start`: `v<version> (<build ID>)`, the device model, the Android version, and RAM, resolution and panel refresh rate; it logs `build=<version>/<build ID>`. The build ID is the first eight characters of `Application.buildGUID`, new for every build, so a tester who quotes it names exactly one binary; `MGD Samples > Build Release APK` writes the same ID into the Build ID column of `releases/manifest.md`, and `MobileBootstrap` adds it to the `session_start` telemetry event as `build`. In the editor there is no build (Play mode reports an all-zero GUID), so the stamp reads `editor`. It differs from the deck's version in three ways: `ShortId` and `Format` are static and pure, so they are tested; there is the `editor` case; and numbers are formatted invariantly, so a comma-decimal phone still shows `90 Hz`. It lives in `Scripts/Shared/` because the bootstrap and the Launcher use the ID too. Copy `BuildStamp.cs`. The tests are `BuildStampTests` in `Assets/_Game/Editor/Tests/`.

`FeedbackLink.cs` shows the closed-test feedback form: in your own project, paste the form's short link into its `url` field and rebuild the APK (here the scene builder sets it from `AboutSceneBuilder.FeedbackFormUrl`, so change it there and rebuild the scene), and the screen shows the link and an *Open feedback form* button that hands it to the browser (the app needs no `INTERNET` permission for that). With no link, a build hides both. The form's fields are in `docs/qa/feedback-form.md`. Android back returns to the samples list; there is no Quit button. Design notes are in the `MGD_MODULE_GDD` vault, note `Samples/About`.
