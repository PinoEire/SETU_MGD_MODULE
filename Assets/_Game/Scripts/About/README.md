# About sample

The Week 8 Lab A build stamp. `BuildStamp.cs` in `Scripts/Shared/` writes the About screen's four lines once in `Start`: `v<version> (<build ID>)`, the device model, the Android version, and RAM, resolution and panel refresh rate; it logs `build=<version>/<build ID>`. The build ID is the first eight characters of `Application.buildGUID`, new for every build, so a tester who quotes it names exactly one binary; `MGD Samples > Build Release APK` writes the same ID into the Build ID column of `releases/manifest.md`, and `MobileBootstrap` adds it to the `session_start` telemetry event as `build`. In the editor there is no build (Play mode reports an all-zero GUID), so the stamp reads `editor`. It differs from the deck's version in three ways: `ShortId` and `Format` are static and pure, so they are tested; there is the `editor` case; and numbers are formatted invariantly, so a comma-decimal phone still shows `90 Hz`. It lives in `Scripts/Shared/` because the bootstrap and the Launcher use the ID too. Copy `BuildStamp.cs`. The tests are `BuildStampTests` in `Assets/_Game/Editor/Tests/`.

`FeedbackLink.cs` shows the closed-test feedback form: in your own project, paste the form's short link into its `url` field and rebuild the APK (here the scene builder sets it from `AboutSceneBuilder.FeedbackFormUrl`, so change it there and rebuild the scene), and the screen shows the link and an *Open feedback form* button that hands it to the browser (the app needs no `INTERNET` permission for that). With no link, a build hides both. The form's fields are in `docs/qa/feedback-form.md`. Android back returns to the samples list; there is no Quit button.

Week 12 adds the build date and commit. `BuildInfo.cs` is the ScriptableObject (*Assets > Create > MGD Samples > Build Info*, where the lab says *Game*); its asset, `Assets/_Game/Settings/BuildInfo.asset`, is referenced by the scene, so it needs no `Resources` folder. `BuildInfoStamper.cs` (`Editor/About/`) writes today's UTC date and the commit's short hash into it before every build; commit the asset with each release. `BuildInfoLabel.cs` shows `Built <date> from <hash>`; with the lab's single `AboutScreen`, use `BuildInfoLabel.Format` for its build line. Copy those three and `Editor/Shared/GitInfo.cs`, which the stamper calls. The worked release checklist is `docs/qa/release-checklist.md`. Design notes are in the `MGD_MODULE_GDD` vault, note `Samples/About`.
