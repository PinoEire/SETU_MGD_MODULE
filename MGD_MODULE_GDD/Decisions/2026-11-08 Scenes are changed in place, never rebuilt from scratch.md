# Scenes are changed in place, never rebuilt from scratch

## Context

Until now every sample scene was generated by an editor script (`Editor/<Sample>/<Sample>SceneBuilder.cs`, menu *MGD Samples > Build <Sample> Scene*, helpers in `Editor/Shared/SampleSceneBuild.cs`), and any change meant changing the builder and regenerating the whole scene. Each run rewrote every object ID, so a one-line change showed up as a scene diff of thousands of lines, the scene and its builder had to be kept in step, and students saw a workflow no studio uses: a scene is an asset that is changed, not regenerated.

## Decision

Once a scene exists it is changed in place, by people and AI tools alike: in the Unity editor (directly, through the Unity MCP tools, or with editor code that opens the scene, edits it and saves it) or by editing the `.unity` file as text. It is never rebuilt from scratch. A one-off editor script may create the first version of a new sample's scene; it is deleted once the scene exists. The fifteen scene builders and `SampleSceneBuild.cs` are removed; the scenes they made are kept as they are.

## Consequences

- Scene diffs show only what changed, because object IDs survive an edit.
- A scene can no longer be rebuilt from code: a scene lost or broken beyond repair comes back from git history.
- Settings that lived as constants in a builder now live in the scene, in the Inspector: the feedback-form link is the `url` field of `FeedbackLink` in the About scene.
- Notes that told readers to rebuild a scene now tell them to change it in place; the builder rows are gone from the Files tables.
- Older decisions that mention builders (such as [[2026-09-15 Back navigation returns to the launcher]] and [[2026-10-04 Every scene pauses on focus loss]]) keep their wording as a record; what they require of a scene still holds.
