# SafeArea

## Goal

Show a HUD that stays inside [[Glossary#Safe area|the safe area]] on every Android phone, in portrait and landscape, while the background still fills the whole screen. Students copy the panel and the script into their own Canvas.

## Lab it supports

Week 2 Lab A, Part E: *Release signing, touch input and safe areas*. The lab sheet gives the procedure; this sample is the finished result students compare against.

## What the student learns

- `Screen.safeArea` is in pixels and changes at runtime (rotation, fold, multi-window), so the panel must re-apply, not just read it once in `Awake`.
- Anchors, not offsets, are the right tool: converting the safe rect to normalised anchors keeps the panel correct at any resolution and Canvas Scaler setting.
- Backgrounds and world-space content stay *outside* the panel. Only interactive and readable UI moves in.
- The Device Simulator is a preview; the phone is the test.
- Assign TextMeshPro text in `Start`, not `Awake`, when the script sits on the same object as the label: TextMeshPro may not have run its own `Awake` yet and the first mesh is never built. Found while verifying the readout; see *Known limits*.

## How to test

1. **Editor:** Window > General > Device Simulator, pick a notched device (Pixel 8, Galaxy S24). Rotate. Expected: the four buttons and the score move in from the notch and the [[Glossary#Gesture bar|gesture bar]]; the background does not.
2. **Phone:** Build And Run with the Android Dev profile. Cover the notch with a finger: nothing sits under it. Swipe up from the bottom edge: no button lives in the gesture zone. Rotate and repeat.
3. **Regression:** change the Canvas Scaler reference resolution to 1920x1080 and check the panel still tracks the safe area. Anchors make this pass; offsets would not.

## Known limits

- Re-checks `Screen.safeArea` every frame. The comparison is a struct equality, no allocation, so it is cheap, but a `Screen.orientation` change callback would be tidier. Kept simple on purpose for a Week 2 audience.
- Does not handle display cut-outs on the *sides* separately from the top; the safe rect already excludes them, which is enough here.
- The scene is built by an editor script rather than by hand. That keeps it reproducible and readable, at the cost of one more file students do not need to copy.
- Verified 2026-09-15: editor Game view at 1080x2400 (layout, layers, readout, no console errors) and a release build running on an Android device.
